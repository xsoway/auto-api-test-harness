契约与变更 → 可执行用例 → 诊断证据

使用 Python、pytest 和 YAML，把接口契约与变更转成可执行用例，再把回归失败转成诊断证据、复现草稿和待验证的补测候选。HTTP、变量传递和业务断言由 Harness 执行；模型可参与规划、候选生成、语义诊断或报告分析。普通回归在 LLMOFF=1 下离线运行。

为什么需要

没有它

  • 手写用例随接口变更过时
  • “断言失败”难以定位根因
  • 补用例靠人肉记忆容易漏

有它之后

  • 契约导入与覆盖缺口扫描，用例持续保鲜
  • 失败治理分流重跑、缺陷与修复
  • Agent Loop 评分去重并回写候选

“把每次回归失败变成下一个可验证的用例。”

功能特性

ah evolve

Agent Loop 与用例演进：收集失败、生成候选、评分去重并回写。

FailureGovernor

把失败分流为缺陷、重跑与修复尝试，支持失败簇与知识复用。

ah add-case

从自然语言生成 YAML 草案，补充边界与异常候选。

Execution Harness

单接口、多步流程、多服务、认证、数据集与跨步依赖。

ah scenario

从 OpenAPI/HAR 提取跨接口依赖，编译为可执行场景。

ah observe

SQLite 追踪、LLM 用量统计与本地看板，全程可观测。

常见问题

一定要用模型吗？

不用。普通回归在 LLMOFF=1 下即可运行；模型仅增强规划、候选生成、诊断与报告。

用什么格式写用例？

YAML —— 单接口、多步流程、数据集、断言与重试。

候选会自动写回吗？

ah evolve 会把高分候选追加到 data/evolution.yaml 供审查；可用 ah evolve --undo 撤回。
